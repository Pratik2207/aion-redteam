# Security Policy

## Scope and intent

`aion-redteam` is an **offensive security testing tool** intended for authorized testing
of AI agents you own or are explicitly permitted to test. It ships adversarial payloads
(prompt injections, jailbreaks, tool-misuse coercions) as test data. Use it only against
your own agents or in engagements where you have written authorization. Do not use it to
attack systems you do not control.

## Trust model (important)

- **Running a target executes its code.** To test an agent, aion-redteam imports the
  `--target` Python file, which runs its module-level code. Only point aion-redteam at
  agent files **you trust**. Treat `--target` like `python that_file.py`.
- **Scenarios are executable test data.** Scenario YAML carries regex patterns that the
  harness compiles and runs. Only load scenarios from sources you trust; review
  community-contributed scenarios (especially their `regex` criteria) before running
  them. Judge input is length-capped and evaluation is time-bounded to limit the impact
  of pathological (ReDoS-prone) patterns, but review is still the first line of defense.
- **aion-redteam makes no network calls of its own** — only the agent under test does.

## Reporting a vulnerability

If you find a security vulnerability **in aion-redteam itself** (for example, a scenario
that executes attacker-controlled code on the host running the harness, or an unsafe
deserialization in the loader), please report it privately:

- Use GitHub's **"Report a vulnerability"** (Security Advisories) on the
  `Cypharia/aion-redteam` repository, **or**
- Email the maintainers (see the repository profile).

Please include reproduction steps and the affected version. We aim to acknowledge within
**5 business days** and to ship a fix or mitigation as quickly as is practical.

Please do **not** open public issues for undisclosed vulnerabilities.

## Handling findings produced by the tool

Reports generated by aion-redteam may contain sensitive payloads and excerpts of agent
output (including any secrets a vulnerable agent leaked). Treat `results.json` and HTML
reports as sensitive artifacts and store them accordingly.

## Supported versions

During the `0.x` pre-release series, only the latest released version receives security
fixes.
